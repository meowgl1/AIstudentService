# 0005: Urgent path uses a hardcoded frontend crisis message; the LLM only triggers it

Status: Accepted
Date: 2026-11-18
Owner: Thomas (frontend constant owned by James)

## Context

Some tickets signal imminent harm. The real risk is a crisis message being generated
or shown automatically off a possibly-wrong LLM classification. `hub.json` gives the
sensitive route but no crisis number, and Torrens-specific numbers are unverified.

## Decision

Urgent is in the MVP in minimal, safe form. Screening distinguishes an "imminent harm"
subset within sensitive and sets `handoffReason: urgent`: like sensitive it is
ESCALATED with no AI draft, but marked top priority for staff. The crisis message text
is a hardcoded constant in the frontend, never generated by the LLM and never in the
API/backend. The LLM only produces the trigger flag. The constant uses only public,
verifiable national numbers: 000 (emergencies) and Lifeline 13 11 14. Torrens-specific
counselling numbers stay out until verified with Torrens.

## Alternatives considered

- LLM-generated or API-delivered crisis text — rejected: variable/wrong crisis content
  is the real danger.
- Declare urgent a stretch goal — rejected: cheap to add safely and strong "safety by
  design" point for the report.

## Consequences

Easier: eliminates variable crisis content; a false positive only shows Lifeline to
someone who doesn't need it (low harm), a false negative still falls to
sensitive/human review. Costs one extra enum value (`urgent`) and no API text. Harder:
the frontend owns a piece of safety-critical copy that must be reviewed.
